      How it works

      When an alert fires, a language model on Azure OpenAI investigates it the way an on-call engineer would: health overview, metrics, logs, traces, recent deploys, config and runbooks. It can only read. It finishes with a structured report, and every recommended change waits for a person to approve it.

      Guardrails

      • Read-only tools. The agent has no tool that changes anything.
      • Human approval. Rollbacks, failovers and rotations are recommendations until someone approves them.
      • Secret redaction. Keys, tokens, passwords and card numbers are masked before tool output reaches the model.
      • Injection handling. Customer-written text in logs is treated as data. Lines that try to instruct the agent are flagged and reported.
      • Limits. Step limit, per-run token budget, repeated-call detection, schema validation of the final report.
      • Demo protection. Per-visitor rate limit, daily spend cap, and recordings of real runs when live runs are unavailable.
